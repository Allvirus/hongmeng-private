# 前端按钮权限接入清单

## 目标

把现有按钮显隐逻辑统一收敛到权限系统，做到：

- 按钮显隐可配置、可追踪；
- 查询与写操作权限分离；
- 页面中不再散落 userInfo.menu.xxx 硬编码。

## 输入产物

- 权限映射源文档： [src/doc/页面按钮权限与 API 映射.md](src/doc/页面按钮权限与API映射.md)
- 后端权限字典： [src/doc/权限点字典.json](src/doc/权限点字典.json)

## 实施顺序

1. 建立权限能力（工具层）
2. 在核心页面接入（业务层）
3. 清理旧判断（收口层）
4. 回归验证（质量层）

## 一、工具层接入

### 1) 新增权限工具函数

建议位置： [src/plugins/utils.js](src/plugins/utils.js)

目标能力：

- hasPerm(code)
- hasAnyPerm(codes)
- hasAllPerm(codes)

数据来源：从 store 的 buttonList 或 permissionSet 获取。

### 2) 新增全局指令

建议位置： [src/plugins/directives.js](src/plugins/directives.js)

新增指令：

- v-permission: 无权限则移除元素
- v-permission-disable: 无权限则禁用元素

建议规则：

- 高风险写操作用 v-permission（直接隐藏）
- 需要保留布局提示的按钮用 v-permission-disable

### 3) 在入口挂载能力

文件： [src/main.js](src/main.js)

动作：

- 将权限函数挂到 Vue.prototype（如 \$perm）
- 确保登录后先拉取权限再渲染关键页面按钮

以下为优先级顺序和挂载建议。

## 三、页面改造范式

### 1) 模板侧

示例：

```vue
<el-button
  v-permission="'level.add'"
  type="primary"
  @click="showEditDlg(false, null)"
>
  新增等级
</el-button>

<el-button v-permission="'level.delete'" type="text" @click="deleteLevel(row)">
  删除
</el-button>
```

### 2) 方法兜底

对关键操作方法建议再做一次运行时校验，避免指令被绕过：

- 进入方法第一行判断 hasPerm(code)
- 无权限直接 return 并提示

## 四、旧逻辑清理清单

重点替换以下模式：

- this.userInfo.menu.xxx
- this.userInfo.menuList.includes(...)

清理时机：

- 每个页面接入完成后立刻清理同页面旧逻辑
- 保留 route fnId 的菜单权限校验，不冲突

## 五、联调与验收

### 1) 角色矩阵测试

至少准备 3 个角色：

- 只读角色：只有 \*.query
- 操作角色：query + add/edit
- 管理角色：query + 全操作

### 2) 必测点

- 按钮显示正确
- 无权限按钮不可操作
- 直接调接口时后端仍能拒绝
- 切换账号后按钮刷新正确

## 六、发布节奏建议

1. 先上线 P0 页面
2. 验证 1~2 天后上线 P1
3. 最后补 P2 与历史页
