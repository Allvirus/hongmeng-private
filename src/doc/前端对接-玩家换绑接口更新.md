# 前端对接-玩家换绑接口更新

## 目的

本次需要前端修复玩家换绑相关页面和调用逻辑，核心变化是：

- 换绑接口新增平台维度 Platform
- Ifun 平台不再按 UserCode 识别玩家，而是按 IfunId 识别
- 查询换绑原始数据时，Ifun 平台需要传 IfunId
- 执行换绑时，Ifun 平台请求体必须带 Platform 和 IfunId

涉及接口：

- GET /api/playerswitch
- GET /api/playerswitch/{playerswitchid}
- GET /api/playerswitch/useraccount/{useraccount}
- GET /api/playerswitch/usercode/{usercode}
- POST /api/playerswitch
- POST /api/playerswitch/new
- DELETE /api/playerswitch/{playerswitchid}

---

## 本次变更摘要

### 1. 换绑记录列表新增查询参数

- 参数名：platform
- 类型：int
- 含义：平台，0=Ifun，1=木勺

- 参数名：ifunId
- 类型：long
- 含义：Ifun 平台玩家数字 ID

说明：

- 非 Ifun 平台仍可继续按 userCode 查询
- Ifun 平台建议优先按 platform + ifunId 查询

### 2. 查询换绑原始数据时，Ifun 平台改为按 IfunId 查找

接口仍然保留：

- GET /api/playerswitch/usercode/{usercode}

但当 platform=0 时：

- 路径中的 usercode 实际上传 IfunId
- 后端会先把该值解析为 long，再按 PlayerInfo.IfunAccountId 查询

也就是说：

- 木勺平台：usercode 传真实 UserCode
- Ifun 平台：usercode 位置传 IfunId 字符串

### 3. 执行换绑时新增必填字段 Platform

POST /api/playerswitch 和 POST /api/playerswitch/new 现在都要求：

- Platform 必传

否则后端直接返回：

- 请选择平台

### 4. Ifun 平台执行换绑时新增 IfunId

请求体新增：

- ifunId

说明：

- Ifun 平台：后端按 PlayerInfo.IfunAccountId、PlayerOrder.IfunId、PlayerRole.IfunId 处理换绑
- 木勺平台：后端仍按 UserCode 处理换绑

### 5. 查询原始数据和创建换绑记录时，返回/提交模型新增字段

- platform
- ifunId

---

## 前端修改点

### 查询表单

玩家换绑页新增或调整以下查询项：

- Platform
- IfunId
- UserCode

建议交互：

- 当平台为 Ifun 时，主查询输入框展示为 IfunId
- 当平台为木勺时，主查询输入框展示为 UserCode

### 原始数据回填

前端点击“查询原始数据”时：

- 若按玩家账号查询，调用 GET /api/playerswitch/useraccount/{useraccount}?platform={platform}
- 若按玩家标识查询：
  - 木勺平台传真实 UserCode
  - Ifun 平台把 IfunId 填到 usercode 路径位置，并追加 platform=0

### 提交换绑

前端提交换绑时：

- Platform 必传
- Ifun 平台必须传 IfunId
- 木勺平台必须传 UserCode

建议前端校验：

- platform=0 时，强制校验 ifunId
- platform=1 时，强制校验 userCode

## 接口说明

## 一、换绑记录分页

### 1. 查询换绑记录

- 地址：GET /api/playerswitch

请求参数：

| 参数名      | 类型   | 必填 | 说明                      |
| :---------- | :----- | :--- | :------------------------ |
| userAccount | string | 否   | 玩家账号，目前后端未使用  |
| userCode    | string | 否   | 玩家标识，木勺平台可用    |
| ifunId      | long   | 否   | Ifun 平台玩家数字 ID      |
| platform    | int    | 否   | 平台，0=Ifun，1=木勺      |
| page        | int    | 否   | 页码，默认 1              |
| pageSize    | int    | 否   | 页大小，默认 5，最大 20   |

说明：

- Ifun 平台建议使用 ifunId + platform=0 查询
- 木勺平台继续使用 userCode + platform=1 查询

请求示例：

```http
GET /api/playerswitch?platform=0&ifunId=645741322&page=1&pageSize=10
```

```http
GET /api/playerswitch?platform=1&userCode=cda7cabddb&page=1&pageSize=10
```

## 三、查询换绑原始数据

### 1. 按玩家账号查询

- 地址：GET /api/playerswitch/useraccount/{useraccount}

请求参数：

| 参数名     | 类型   | 必填 | 说明                 |
| :--------- | :----- | :--- | :------------------- |
| useraccount| string | 是   | 玩家账号             |
| platform   | int    | 否   | 平台，0=Ifun，1=木勺 |

说明：

- 如果同一个 userAccount 可能跨平台重复，前端应始终传 platform

请求示例：

```http
GET /api/playerswitch/useraccount/ms645741322?platform=0
```

返回示例：

```json
{
  "data": {
    "platform": 0,
    "userAccount": "ms645741322",
    "userCode": "cda7cabddb",
    "ifunId": 645741322,
    "ajob": "张三",
    "ajobId": 12,
    "bjob": "李四",
    "bjobId": 28,
    "cjob": "王五",
    "cjobId": 31
  },
  "code": 200
}
```

### 2. 按玩家标识查询

- 地址：GET /api/playerswitch/usercode/{usercode}

请求参数：

| 参数名   | 类型   | 必填 | 说明 |
| :------- | :----- | :--- | :--- |
| usercode | string | 是   | 木勺传 UserCode，Ifun 传 IfunId 字符串 |
| platform | int    | 否   | 平台，0=Ifun，1=木勺 |

规则说明：

- platform=1 时：按 PlayerInfo.UserCode 查询
- platform=0 时：后端会把 usercode 解析成 long，并按 PlayerInfo.IfunAccountId 查询
- 如果 platform=0 但传入的不是数字，后端会返回：ifun平台请传ifunid

请求示例：

木勺平台：

```http
GET /api/playerswitch/usercode/cda7cabddb?platform=1
```

Ifun 平台：

```http
GET /api/playerswitch/usercode/645741322?platform=0
```

## 四、执行换绑

### 1. 常规换绑

- 地址：POST /api/playerswitch

说明：

- 如果传了 targetTime，则只替换 targetTime 之后的订单数据
- 注册信息与角色数据会按当前玩家主键整体处理

请求体字段：

| 字段名      | 类型      | 必填 | 说明 |
| :---------- | :-------- | :--- | :--- |
| platform    | int       | 是   | 平台，0=Ifun，1=木勺 |
| userAccount | string    | 否   | 玩家账号 |
| userCode    | string    | 否   | 木勺平台玩家标识 |
| ifunId      | long      | 否   | Ifun 平台玩家数字 ID |
| targetTime  | datetime  | 否   | 生效时间分界点 |
| ajobId      | int       | 否   | 原 A 岗 Id，页面回填用 |
| ajob        | string    | 否   | 原 A 岗姓名，页面回填用 |
| bjobId      | int       | 否   | 原 B 岗 Id，页面回填用 |
| bjob        | string    | 否   | 原 B 岗姓名，页面回填用 |
| cjobId      | int       | 否   | 原 C 岗 Id，页面回填用 |
| cjob        | string    | 否   | 原 C 岗姓名，页面回填用 |
| ajobIdAfter | int       | 是   | 新 A 岗 Id |
| bjobIdAfter | int       | 是   | 新 B 岗 Id |
| cjobIdAfter | int       | 是   | 新 C 岗 Id |

前端提交规则：

- Ifun 平台必须提交：platform=0、ifunId
- 木勺平台必须提交：platform=1、userCode

Ifun 请求示例：

```json
{
  "platform": 0,
  "userAccount": "ms645741322",
  "userCode": "cda7cabddb",
  "ifunId": 645741322,
  "targetTime": "2026-03-20T00:00:00",
  "ajobId": 12,
  "ajob": "张三",
  "bjobId": 28,
  "bjob": "李四",
  "cjobId": 31,
  "cjob": "王五",
  "ajobIdAfter": 15,
  "bjobIdAfter": 29,
  "cjobIdAfter": 35
}
```

木勺请求示例：

```json
{
  "platform": 1,
  "userAccount": "abc123",
  "userCode": "cda7cabddb",
  "targetTime": "2026-03-20T00:00:00",
  "ajobId": 12,
  "ajob": "张三",
  "bjobId": 28,
  "bjob": "李四",
  "cjobId": 31,
  "cjob": "王五",
  "ajobIdAfter": 15,
  "bjobIdAfter": 29,
  "cjobIdAfter": 35
}
```

### 2. 反向时间换绑

- 地址：POST /api/playerswitch/new

说明：

- 这是另一种时间分界逻辑
- 如果传了 targetTime，则处理 targetTime 之前的数据

前端请求体与 POST /api/playerswitch 完全一致，只是接口地址不同。

使用建议：

- 正常场景走 POST /api/playerswitch
- 只有在业务明确要求“按 targetTime 之前的数据换绑”时才走 POST /api/playerswitch/new

---

## 五、删除换绑记录

### 1. 删除记录

- 地址：DELETE /api/playerswitch/{playerswitchid}

请求参数：

| 参数名         | 类型 | 必填 | 说明 |
| :------------- | :--- | :--- | :--- |
| playerswitchid | int  | 是   | 换绑记录 ID |

说明：

- 删除的是换绑记录本身
- 不会自动回滚已经执行过的数据换绑结果

---

## 前端联调建议

- 换绑页新增平台选择，并作为查询和提交的前置条件
- Ifun 平台查询原始数据时，把输入框值当 IfunId 传递，不要再按 UserCode 理解
- Ifun 平台提交换绑时务必带上 ifunId
- 木勺平台继续沿用 userCode，但也要补传 platform
- 删除换绑记录前，前端应提示“仅删除记录，不回滚已生效数据”
