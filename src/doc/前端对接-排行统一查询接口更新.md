# 前端对接-排行统一查询接口更新

## 目的

本次排行功能调整，目标是让前端可以在同一套页面结构中完成以下查询：

- 个人充值排行
- 个人换包排行
- 部门充值排行
- 部门换包排行
- 自定义时间区间查询

后端新增统一接口：

- GET /api/rank/query

原有接口：

- GET /api/rank/today
- GET /api/rank/yesterday
- GET /api/rank/week
- GET /api/rank/lastweek
- GET /api/rank/month
- GET /api/rank/lastmonth

仍可继续使用，但新的排行页建议统一改为调用 GET /api/rank/query。

## 本次变更摘要

### 1. 页面交互建议

建议前端页面采用以下结构：

- 第一层 Tab：个人 / 部门
- 第二层 Tab：充值 / 换包
- 顶部筛选：开始日期、结束日期
- 可选筛选：岗位、区服
- 内容区：排行榜列表

这样前端只需要维护一套页面逻辑，通过切换参数调用统一接口即可。

### 2. 统一接口支持的查询维度

- scope：person / department
- metric：recharge / device
- job：A / B / C
- startDate：开始日期
- endDate：结束日期
- areaName：区服名称，可选
- topN：返回前 N 条，可选

### 3. 旧接口用途

原有 today、yesterday、week、lastweek、month、lastmonth 仍可作为快捷排行接口使用。

如果前端新页面已经具备日期选择器，建议优先使用统一接口，不再依赖多个固定时间接口。

## 前端修改点

### 1. 查询表单

新增或统一以下查询项：

- 统计对象：个人 / 部门
- 指标类型：充值 / 换包
- 岗位：A / B / C
- 开始日期：startDate
- 结束日期：endDate
- 区服：areaName，可选
- 返回条数：topN，可选

推荐默认值：

- scope=person
- metric=device
- job=A
- startDate=今天
- endDate=今天
- topN=50

### 2. 页面展示

统一排行列表建议展示以下列：

- 排名：rank
- 名称：name
- 数值：value

其中：

- 个人充值：name 为员工名，value 为充值金额
- 个人换包：name 为员工名，value 为换包数
- 部门充值：name 为部门名，value 为充值金额
- 部门换包：name 为部门名，value 为换包数

前端可根据 metric 动态切换数值列标题：

- recharge 时显示“充值金额”
- device 时显示“换包数”

### 3. 快捷时间建议

虽然统一接口支持任意时间区间，但前端仍建议保留快捷按钮：

- 今日
- 昨日
- 本周
- 上周
- 本月
- 上月

这些快捷按钮只需要回填 startDate / endDate，然后调用统一接口即可。

## 接口说明

## 一、统一排行查询

- 地址：GET /api/rank/query

请求参数：

| 参数名    | 类型   | 必填 | 说明                                                |
| :-------- | :----- | :--- | :-------------------------------------------------- |
| scope     | string | 否   | 统计对象，person=个人，department=部门，默认 person |
| metric    | string | 否   | 指标类型，recharge=充值，device=换包，默认 device   |
| job       | string | 否   | 岗位，A / B / C，默认 A                             |
| startDate | string | 否   | 开始日期，格式 yyyy-MM-dd，默认今天                 |
| endDate   | string | 否   | 结束日期，格式 yyyy-MM-dd，默认今天                 |
| areaName  | string | 否   | 区服名称                                            |
| topN      | int    | 否   | 返回前 N 条，默认 50，最大 200                      |

说明：

- startDate 与 endDate 只需要传日期，不需要传时分秒。
- 如果 startDate 大于 endDate，后端会自动交换顺序。
- 未传 areaName 时，默认查询全部区服。
- 返回数据已经按数值倒序排序。

## 二、返回结构

返回示例：

```json
{
  "code": 200,
  "data": {
    "scope": "person",
    "metric": "device",
    "job": "A",
    "startDate": "2026-04-01T00:00:00",
    "endDate": "2026-04-09T00:00:00",
    "items": [
      {
        "rank": 1,
        "name": "张三",
        "value": 128
      },
      {
        "rank": 2,
        "name": "李四",
        "value": 96
      }
    ]
  }
}
```

字段说明：

| 字段名    | 类型     | 说明               |
| :-------- | :------- | :----------------- |
| scope     | string   | 本次查询的统计对象 |
| metric    | string   | 本次查询的指标类型 |
| job       | string   | 本次查询的岗位     |
| startDate | datetime | 开始日期           |
| endDate   | datetime | 结束日期           |
| items     | array    | 排行结果           |

items 中字段说明：

| 字段名 | 类型    | 说明                         |
| :----- | :------ | :--------------------------- |
| rank   | int     | 排名，从 1 开始              |
| name   | string  | 员工名或部门名               |
| value  | decimal | 数值，可能是充值金额或换包数 |

## 三、前端调用示例

### 1. 个人充值排行

```http
GET /api/rank/query?scope=person&metric=recharge&job=A&startDate=2026-04-01&endDate=2026-04-09
```

### 2. 个人换包排行

```http
GET /api/rank/query?scope=person&metric=device&job=A&startDate=2026-04-01&endDate=2026-04-09
```

### 3. 部门充值排行

```http
GET /api/rank/query?scope=department&metric=recharge&job=A&startDate=2026-04-01&endDate=2026-04-09
```

### 4. 部门换包排行

```http
GET /api/rank/query?scope=department&metric=device&job=A&startDate=2026-04-01&endDate=2026-04-09
```

### 5. 带区服筛选的换包排行

```http
GET /api/rank/query?scope=person&metric=device&job=B&startDate=2026-04-01&endDate=2026-04-09&areaName=S1&topN=20
```

## 四、前端迁移建议

### 方案一：保留旧页，新增统一排行页

适用场景：

- 旧页面已经上线，不希望影响现有逻辑
- 新页面需要支持更灵活的筛选与切换

做法：

- 原有固定时间排行页继续调用旧接口
- 新排行页全部切到 GET /api/rank/query

### 方案二：旧页逐步收口到统一接口

适用场景：

- 希望后续只保留一个排行接口入口

做法：

- 今日按钮对应 startDate=endDate=今天
- 昨日按钮对应 startDate=endDate=昨天
- 本周按钮回填本周开始日期和今天
- 上周按钮回填上周开始日期和上周结束日期
- 本月按钮回填本月第一天和今天
- 上月按钮回填上月第一天和上月最后一天

这样前端不再依赖多个固定时间接口。

## 五、统计口径说明

### 1. 换包排行

换包排行继续复用后端现有三桶去重算法，口径与现有统计保持一致：

- 有效设备号按设备号去重
- 无设备号但有 IP 时，按同天同 IP 去重
- 无设备号且无 IP 时，每条各计 1

同时，换包排行只统计在所选时间区间内有创角记录的用户。

### 2. 部门换包排行

部门换包不是整个部门做全局设备去重，而是：

- 先按员工维度统计换包数
- 再汇总到部门

前端只需要展示结果，不需要自行处理统计逻辑。

### 3. 充值排行

充值排行按订单金额聚合：

- 个人充值：按员工汇总
- 部门充值：按员工所属部门汇总

## 六、前端兼容提示

旧接口返回结构仍然是旧版 RankDto，主要用于固定时间换包排行。

统一接口返回结构为 RankQueryDto，与旧接口不同，前端接入时需要注意：

- 旧接口返回的是分岗位字段对象
- 新接口返回的是单组 items 列表

建议新页面统一按 RankQueryDto 处理，避免同时维护两套渲染逻辑。

## 七、推荐实施顺序

1. 先新增统一排行页，全部基于 GET /api/rank/query。
2. 再将旧页面上的快捷时间按钮逐步切换到统一接口。
3. 最终如确认旧接口无前端依赖，再考虑收口旧接口。
